## 1. 아키텍처 · 설계 패턴

### 데이터 드리븐 설계
게임 수치를 코드가 아닌 데이터로 관리합니다. CSV 파싱 구조로 데이터 테이블을 적재하고, 파일 입출력으로 세이브를 처리합니다. 기획 수치 변경이 코드 수정 없이 반영됩니다.

### ScriptableObject 적극 활용
각종 데이터 테이블을 ScriptableObject로 구성합니다. 정적 기획값은 SO가 보유하고, 동적 런타임 상태는 SO에 두지 않는다는 원칙을 지킵니다.

### 싱글톤
매니저 계층(입력·화면 감시·데이터 등)을 제네릭 싱글톤으로 관리합니다. 도메인 리로드·씬 전환·종료 순서에 안전하도록 구성했습니다.

### 옵저버 패턴 (이벤트 기반 발행–구독)
정렬 성공·화면 변화·재화 변경 등을 이벤트로 발행하고, 관심 있는 쪽이 구독합니다. 발행자와 구독자가 서로를 직접 참조하지 않아 결합도가 낮습니다.

### 팩토리 패턴
타워·몬스터 등 런타임 생성 객체를 팩토리 패턴으로 생성합니다. 생성 책임을 한 곳에 모아 타입별 분기를 캡슐화했습니다.

### 오브젝트 풀링
런타임 중 잦은 생성·파괴를 피하기 위해 오브젝트 풀을 사용합니다. GC 부담과 프레임 스파이크를 줄입니다.

### 의존성 역전 (인터페이스)
구현이 아니라 인터페이스(계약)에 의존합니다. 예로 `IDraggable` — `PointerHandler`는 이 계약만 보고 동작해, 드래그 대상(`Piece`)을 자유롭게 교체·확장할 수 있습니다.

### 상태 조합 기반 표시 판정 (State)
`SlotDisplayMode { Normal, NormalWithActive, NormalWithActiveQueue, Destroyed }` — 슬롯 상태 × 포탑 보유 여부의 조합으로 표시 모드를 판정합니다. 포탑이 죽으면 모드가 자동 하락해, 비주얼 복구가 별도 코드 없이 따라옵니다.

## 2. 3-Sort 슬롯 시스템

### 오브젝트 풀 + 데이터→비주얼 단방향 동기화
27개 기물을 셀에 영구 매핑하고, `SetByID()`로 스프라이트를 교체 + `SetActive`로 토글합니다. 런타임 중 생성·파괴를 하지 않아 가볍습니다. 논리 데이터를 유일한 진실로 두고, 비주얼은 데이터를 pull해 갱신하는 단방향 구조입니다.

### 정적 조회 창구 — PieceQuery / SlotQuery / StageQuery
세 도메인이 동일 패턴의 정적 조회 창구를 가집니다. 데이터 보유는 `DataManager`에 위임하고, 도메인 조회·가공만 담당합니다.

### 좌표 ↔ 1차원 인덱스 변환 — SGrid
`SGrid2D<T>`는 `cells[y * size.x + x]`로 2차원 좌표를 1차원 배열에 매핑합니다. 슬롯 도메인엔 2차원이 오버스펙이라 `SGrid1D<T>`로 개조해 사용합니다.

## 3. UI · 연출

### UGUI 반응형 UI
CanvasScaler Expand·레이아웃 그룹 등으로 화면비·해상도에 대응하는 반응형 UI를 구성합니다. 노치·홈 인디케이터에 대응하는 세이프 에리어 처리를 포함합니다.

### DOTween
스테이지 선택 애니메이션 연출(크로스 슬라이드·배경 크로스페이드)에 사용합니다.

---

## 4. 현지화

### Unity Localization
한국어·영어·일본어 현지화를 Unity Localization으로 구현합니다. 기능 자체가 어드레서블(Addressables) 연동으로 동작합니다.

### Google Sheets API
현지화 문구를 Google Sheets에서 관리하고, Sheets API로 String Table에 단방향 연동합니다. 기획팀이 시트를 수정하면 문구가 갱신됩니다.

---

## 5. 비동기 · 오디오

### 커스텀 async 비동기
사운드 매니저의 오디오 믹서 로딩을 커스텀 async 비동기로 구현합니다. 로딩 완료를 기다린 뒤 후속 처리가 이어지도록 했습니다.

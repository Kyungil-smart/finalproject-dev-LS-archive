## 구현 내용

SpawnManager

#### 구현 목적

몬스터, 타워 오브젝트 생성 관리자

#### 구현 방법

- 인게임 내 몬스터, 타워 생성을 관리하는 구조로 설계했다.
- Factory패턴으로 오브젝트 생성, 요청만하면 생성할 수 있게 했다.
- 몬스터는 프리팹 없이 코드기반 생성
- 타워는 프리팹기반 생성

#### 설계 의도

- DontdestroyOnLoad선언을 하여 씬 전환이 일어나도 파괴되지 않는 관리자
중복 생성되지 않게 Singleton으로 구성
- 오브젝트 생성요청을 받아 관리하기 위해 구성

#### 결과

- 스폰매니저 인스턴스로 접근해 원하는 오브젝트 생성을 요청할 수 있게 됨

#### 회고

- 매니저(관리자)지만 팩토리가 없다면 오브젝트를 생성할 수 없는 의존과 종속이 생겼다.
- 팩토리가 없어도 작동할 수 있는 구조, 없을 때 새로 생성하는 구조로 설계를 할 필요가 있어보임
- 몬스터 스프라이트를 자식객체로 분리 적용하기 위해 Instantiate(new GameObject, transform)로 생성을 했을 시
게임오브젝트를 생성하고 복사해오는 문제로 스폰마다 빈 오브젝트가 생성되는 걸 확인
new GameObject로 생성 후 SetParent를 활용해 자식 개체로 전환하는 방식으로 변경

## 구현 내용

PoolManager(투사체)

#### 구현 목적

- 투사체 오브젝트를 재활용할 수 있게 관리할 수 있게 설계

#### 구현 방법

- 타워 생성시 타입에 해당하는 투사체 풀 생성
- 풀 형태 `Dictionary<GameObject prefab, Queue<GameObject> objQueue>`
- 키 값이 같은 풀 생성 요청 시 무시
- Get 요청시 큐가 비었을 때 오브젝트 추가 생성
- IPoolable 인터페이스로 풀가능 객체 구현
(OnSpawn, OnDeSpawn)

#### 설계 의도

- 투사체는 프레임마다 자주 생성과 삭제가 일어날 것이라 판단
재활용할 수 있는 구조로 설계할 필요성 느낌

#### 결과

- 타워의 종류가 달라도 투사체의 종류가 같다면 재사용 가능하게 되었음

#### 회고

- 풀 생성 후 씬전환 시 참조한 오브젝트가 Missing상태가 되어버리는 것을 확인
- 재활성화 시 재참조 처리

## 구현 내용

SoundManager

### 구현 목적

- 필요한 객체에서 호출 시 소스를 재생하기 위함

#### 구현 방법

- 싱글톤 패턴
- SOSoundTable 참조
- 오디오믹서 로드 중 어드레서블 AsyncOperationHandle ⇒  CustomResourceAsyncHandle 구현

#### 설계 의도

- 오디오 믹서 로드가 완료 된 후 믹서 그룹생성 후 연결
- EAudioEnum을 인수로 받아 SOSoundTable를 재생

#### 결과

- 성공적으로 믹서로드가 완료되면 그룹생성과 연결이 됨
- 재생 로직은 미구현

#### 회고

- CustomHandle.Completed Action에 구독처리 시 
Handle을 Struct타입으로 설계하니 얕은 복사로 인해 bool변수 isCompleted의 변경이 반영되지 않음
Class타입으로 변경하여 변경사항이 반영되도록 변경

Towers

#### 구현 목적

- 하나의 타워 클래스로 여러종류 타워를 구현하기 위함

#### 구현 방법

- Towers 클래스 하나에 STowerInfo 데이터에 따라 종류 구현

#### 설계 의도

- 포탑 종류별로 프리팹을 생성해 관리하려 했으나
포탑마다 데이터가 다른 점을 이용해
하나의 클래스만으로 종류를 구현

#### 결과

- 같은 Towers컴포넌트지만 다른 동작을 하는 타워를 생성 가능해짐

#### 회고

- 공격 코루틴을 중지할 때 `StopCoroutine()` 만 사용해 중지할 코루틴을 못찾는 경우나 탐색 과정 중 자원 소모 인지
atkCoroutine에 할당하여 StopCoroutine(*_atkCoroutine)을 사용해 안전처리*

## 구현 내용

몬스터팩토리

### 구현 목적

- 몬스터 종류별로 생성

#### 구현 방법

- Factory패턴을 사용
- new GameObject()로 생성 후 필요한 컴포넌트를 추가해 생성
- 스프라이트의 경우 자식 개체를 생성해 결합

#### 설계 의도

- 종류에 따라 필요한 컴포넌트를 붙여 몬스터를 생성할 필요가 있기에
조립식으로 생성하기 쉬운 팩토리패턴을 채택

#### 결과

- 종류에 따라 스프라이트를 다르게 데이터도 다르게 몬스터를 생성 할 수 있게 됨

#### 회고

- 스프라이트 자식객체설정을 `Instantiate(new GameObject, transform)` 으로 하니
빈 오브젝트가 스폰마다 생성 되는 것을 확인
`new GameObject()` 후 `transform.SetParent()` 로 부모설정하여 해결

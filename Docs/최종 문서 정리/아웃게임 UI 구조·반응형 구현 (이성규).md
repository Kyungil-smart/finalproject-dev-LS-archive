# 아웃게임 UI 구조·반응형 구현 (이성규)

**팀명**: 7팀 / 유닉온 기업협약 · 총알소녀  
**담당**: 이성규 (아웃게임 로비 UI 전반)  
**엔진**: Unity 6.3 LTS / URP 2D / uGUI(Canvas)  
**작성일**: 2026-07-13  

---

## 0. 문서 목적

아웃게임(로비) UI를 피그마 기획에 맞춰 앵커·레이아웃·반응형까지 고려해 Unity 에디터에서 구현한 과정을 정리합니다. 기능 나열이 아니라 "어떤 구조로 잡았고, 왜 그렇게 했는가"에 초점을 둡니다. 개별 기능 설명은 기술 문서 5장을 참조합니다.

---

## 1. 설계 목표

피그마 시안을 기기 해상도·노치 편차와 무관하게 재현하는 것이 목표였습니다. 모바일은 기종마다 화면비·노치·홈 인디케이터가 달라, 한 해상도에서 맞춘 배치가 다른 기기에서 깨지기 쉽습니다. 그래서 다음을 원칙으로 잡았습니다.

- **앵커 기반 배치** — 절대 좌표가 아니라 화면 가장자리·중앙 기준 앵커로 배치해 화면비가 달라져도 요소가 제자리를 지키게 함.
- **역할별 레이어 분리** — 배경·상단·중앙·하단·팝업을 캔버스 계층으로 나눠 서로 간섭 없이 독립 배치·전환.
- **반응형 일원화** — 해상도·세이프 에리어 변화를 한 경로로 감지해 각 요소가 스스로 재배치.

---

## 2. 로비 캔버스 5분리 구조

로비를 역할별 5개 계층으로 분리했습니다. 각 계층은 독립된 앵커 체계를 가져, 한 계층을 손봐도 다른 계층 배치가 흔들리지 않습니다.

| 계층 | 역할 | 앵커/배치 방침 |
|---|---|---|
| BG | 배경 이미지 | 화면 전체 stretch. 세이프 에리어 미적용(끝까지 꽉 차야 함) |
| TopInfo | 상단 정보(재화·라벨) | 상단 고정 띠. 노치만큼 아래로 오프셋 |
| Window | 중앙 콘텐츠(탭별 윈도우) | 중앙 기준. 탭 전환으로 교체 |
| UnderBar | 하단 탭바 | 하단 고정 띠. 인디케이터만큼 위로 오프셋 |
| Popup | 팝업·딤 | 최상단. 공용 딤 관리 진입점 |

### CanvasScaler — Expand 모드

CanvasScaler를 **Scale With Screen Size / Expand** 모드로 두어, 기준 해상도보다 넓거나 좁은 화면에서도 UI가 잘리지 않고 확장되도록 했습니다. 세로 고정 게임이라 세로 기준을 유지하되, 가로 편차를 Expand가 흡수합니다.

---

## 3. 세이프 에리어 대응

노치·펀치홀·홈 인디케이터 기기에서 상·하단 띠가 시스템 UI에 가려지지 않도록 두 컴포넌트로 대응했습니다. 공통 설계는 **"원래 앵커·크기는 유지하고 오프셋만 민다"** 입니다. 컨테이너를 새로 끼우는 계층 변경 없이 기존 오브젝트에 바로 부착할 수 있어, 피그마 기준 배치를 훼손하지 않습니다.

### `SafeAreaOffset` — 고정 높이 띠 전용

좌우 stretch + 세로 고정 높이 오브젝트(상단/하단 띠)의 `anchoredPosition.y`만 세이프 에리어 여백만큼 밉니다. 상단 띠는 노치 높이만큼 아래로, 하단 띠는 인디케이터 높이만큼 위로. 앵커·높이는 그대로라 자식 배치가 안 깨집니다.

### `SafeAreaPadding` — 4방향 오프셋

`offsetMin`/`offsetMax`를 4방향(상·하·좌·우 선택) 세이프 에리어만큼 밀어, 자체 앵커를 가진 오브젝트에 그대로 적용합니다.

### 공통 처리

두 컴포넌트 모두 세이프 에리어 여백(픽셀)을 **캔버스 스케일로 환산**해 UI 단위로 반영합니다. 픽셀을 그대로 쓰면 CanvasScaler가 적용된 화면에서 어긋나기 때문입니다. 원래 위치·오프셋을 `Awake`에서 백업해 두고, 그 값을 기준으로 매번 다시 계산해 반복 적용에도 값이 누적되지 않습니다. 직전 세이프 에리어와 같으면 조기 반환해 불필요한 재배치를 막습니다.

---

## 4. 반응형 일원화 — `ScreenWatcher` 단일 감시

Unity는 해상도 변경 콜백을 기본 제공하지 않아 폴링이 정석입니다. 여러 컴포넌트가 각자 매 프레임 폴링하면 낭비라, **한 곳(`ScreenWatcher`)에서만 감시하고 변경된 프레임에만 이벤트를 발행**하는 구조로 잡았습니다.

- 매 프레임 `Vector2Int` 화면 크기 비교(struct 비교라 힙 할당·GC 없음), 변화가 있을 때만 `OnResolutionChanged` 발행.
- 세이프 에리어 컴포넌트·슬롯 레이아웃·스포너 등이 이 이벤트를 구독해 각자 영역만 재배치.
- 구독자는 `OnDestroy`에서 반드시 해제(죽은 참조 방지).

에디터에서 게임뷰 해상도를 바꾸거나 기기에서 회전·폴더블 접힘이 일어나도 한 이벤트로 전 UI가 함께 갱신됩니다.

## 5. 탭 전환 일괄 처리 — `LobbyTabBar`

탭 하나를 누르면 (중앙 윈도우 전환 + 탭 활성 표시 + 상단 라벨 갱신)이 한 번에 일어나야 합니다. 이 세 가지가 흩어지면 상태가 어긋나기 쉬워, **한 탭에 묶이는 요소를 `TabEntry` 구조체로 묶고 인덱스로 일괄 토글**했습니다.

- `TabEntry` = 버튼 + 활성 이미지 + 대응 윈도우 + 라벨 키 + 라벨 아이콘.
- 버튼 콜백은 루프에서 인덱스를 지역 변수로 캡처해 등록(클로저 캡처 함정 회피).
- 같은 탭 재선택은 무시해 불필요한 재전환 방지.
- 상단 라벨은 문구가 아니라 **로컬라이즈 키**를 `LocalizeStringEvent`에 꽂아, 언어 전환 시 자동 갱신(별도 구독 불필요).

---

## 6. 피그마 → 에디터 구현 워크플로

시안을 눈대중으로 옮기지 않고, 계층·앵커·간격을 시안 구조에 맞춰 재현했습니다.

- 피그마의 프레임 구조를 캔버스 5계층에 대응.
- 요소별로 시안의 정렬 기준(상단 고정·중앙·하단 고정)을 앵커로 옮김 — 절대 좌표 사용 최소화.
- 고정 띠(상단/하단)에는 세이프 에리어 컴포넌트를 부착해 노치 편차를 흡수.
- 반응형·세이프 에리어는 에디터 게임뷰에서 여러 해상도·세이프 에리어 프리셋으로 즉시 검증.

---

## 7. 결과·한계

**결과** — 세로 고정 기준에서 화면비·노치가 다른 기기에서도 로비 배치가 피그마 시안에 근접하게 재현됩니다. 계층 분리로 이후 윈도우 추가·팝업 확장이 기존 배치를 건드리지 않고 가능합니다.

**한계** — 세이프 에리어 대응은 로비 씬에 한정됩니다. 인게임 씬 상단 UI(HP·웨이브)는 동일 컴포넌트로 확장 가능하나 우선순위상 미적용입니다. (버그 리스트 BUG-04)

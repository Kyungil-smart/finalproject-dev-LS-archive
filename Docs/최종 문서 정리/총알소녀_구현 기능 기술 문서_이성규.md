## 0. 문서 목적

담당 파트의 구현 기능을 기능 단위로 정리하고, 각 기능의 담당 클래스·동작 방식·주요 설계 결정을 함께 기록합니다. 인수인계·검증 확인용이며, 세부 개발 이력은 작업노트(Day 1~42)를 참조합니다.

## 1. 관통 설계 원칙

파트 전반에 일관되게 적용한 원칙입니다. 개별 기능은 이 원칙의 사례입니다.

- **단방향 데이터→비주얼 동기화** — 논리 데이터를 유일한 진실로 두고, 비주얼은 데이터를 pull해 갱신(SetByID).<br>데이터를 먼저 바꾸고 표현을 뒤따르게 해 상태 불일치를 차단.
- **인터페이스 기반 디커플링** — 입력·표시·전투 경계를 인터페이스로 끊음(`IDraggable`, `ITurretPresence`, `ITower`, `IDamageable`).<br>호출부가 구체 타입을 모르게 해 교체·확장 여지 확보.
- **책임 분리** — 한 클래스가 "무엇을/언제/어떻게"를 나눠 가짐.<br>예: 보충은 매니저가 "언제", 공급기가 "무엇을".
- **명시적 교체 이음새(seam)** — 임시 구현·캐스팅 지점에 "인터페이스로 올리면 제거" 주석을 남겨 리팩터링 경로를 코드에 표시.
- **정적 데이터/동적 상태 분리** — 수치는 ScriptableObject, 런타임 상태는 별도 컴포넌트.<br>SO에 동적 상태를 두지 않음.

## 2. 코어 인프라

### 2-1. 제네릭 싱글톤 (`Singleton<T>` / `SingletonBase`)

단일 인스턴스 보장·씬 전환 생존·종료 안전성을 제공합니다. 자식은 `Awake`가 아니라 `Init()`을 오버라이드 — 베이스가 "살아남은 단일 인스턴스"에서만 `Init()`을 호출하므로 자식이 중복 인스턴스 체크를 직접 할 필요가 없습니다.

- 도메인 리로드를 꺼도 static 상태가 남지 않도록, 비제네릭 `SingletonBase`가 리셋 델리게이트를 레지스트리로 모아 `RuntimeInitializeOnLoadMethod`로 일괄 초기화.<br>(제네릭 클래스엔 해당 어트리뷰트를 못 달아 분리)
- 종료 시 재생성 방지(`IsQuitting`), `OnDestroy`에서 자기 참조만 정리.

### 2-2. 매니저 허브 (`GameManager`)

핵심 매니저들의 등록 진입점입니다. 참조 순서를 고려해 `DataManager`를 가장 먼저 등록하고, 각 매니저를 `Instance` 접근으로 생성해 자식으로 붙입니다. 앱 시작 시 현지화 복원 코루틴도 여기서 기동합니다.

### 2-3. 입력 (`InputManager` / `PointerHandler` / `IDraggable`)

- `InputManager` — Input System 기반. 원시 입력을 받아 화면→월드 좌표까지 변환한 뒤 다운/드래그/업 이벤트를 발행.<br>그 이상(무엇이 잡혔는지)은 다루지 않음.
- `PointerHandler` — 입력을 받아 최근접 기물을 잡고 `IDraggable`에 위임.<br>구체 타입(Piece)을 모름. 멀티터치 2번째 입력은 무시.
- 모바일 터치·에디터 마우스를 한 경로로 통합.

### 2-4. 화면 감시 (`ScreenWatcher`)

Unity가 해상도 변경 콜백을 기본 제공하지 않아, 한 곳에서 폴링하고 변경 프레임에만 이벤트를 발행합니다. 슬롯 레이아웃·세이프 에리어 등 여러 컴포넌트가 각자 폴링하지 않도록 단일 감시원으로 둔 구조입니다.

## 3. 3-Sort 슬롯 시스템 (핵심)

3×3 슬롯 × 셀 3칸(총 27칸)에서 같은 기물 3개를 정렬해 포탑을 소환하는 핵심 루프입니다. 월드 스페이스 스프라이트라 UGUI 레이아웃을 못 써 좌표·스케일을 직접 계산합니다.

### 3-1. 데이터 구조 (`SGrid1D` / `CellRuntimeData` / `Slot`)

- 슬롯의 셀 상태를 `SGrid1D<CellRuntimeData>`가 보유.<br>매치-3에서 쓰던 2차원 격자를 1차원으로 개조.
- `Slot`이 셀 상태를 단독 소유하고 정렬 판정·셀 조작만 담당.<br>전투 피격(HP)은 `SlotHealth`로 분리.
- 셀 배치·비우기는 반드시 `Slot`의 메서드로만 — 데이터를 먼저 바꾸고 대응 Piece 비주얼을 `SetByID`로 갱신(단방향).

### 3-2. 드래그·드롭 판정 (`Piece` / `SlotBoardManager` / `CellHighlighter`)

- 잡기·놓기·호버를 콜라이더 판정이 아니라 **보드 최근접 셀(거리 비교)**로 처리.<br>손가락 오차·기물 가림을 흡수하고 물리 쿼리를 제거.
- `Piece`는 자기 셀에 영구 매핑되고 데이터만 이동 — 도착 셀 Piece가 켜지고 출발 셀 Piece가 꺼지는 흐름.
- 같은 슬롯 내 이동 시 "도착 먼저 → 출발 나중" 순서로 처리해, 전체가 빈 순간에 보충이 끼어드는 사고를 방지.

**설계 변천 — 물리 판정(1차) → 최근접 셀 거리(최종)**

[대조도 보기 (Google Drive)](https://drive.google.com/file/d/1l2v6nJ0ThaEizMeA7vdhNn6aIwB1SB9M/view?usp=sharing)

1차 설계(Day 6, 대체됨)와 최종 설계(Day 40)를 파이프라인 단위로 대조한 그림. 대체 텍스트로 핵심 차이를 옮기면 다음과 같음.

- **잡기** — 1차: `Physics2D.OverlapPoint`(Piece 레이어 raycast)로 콜라이더에 걸린 기물을 잡음.<br>최종: `SlotBoardManager.FindNearestGrabbable`(거리 스냅 반경)로 최근접 기물을 잡음.
- **드롭** — 1차: Cell 레이어 `OverlapPoint` 히트로 배치 셀 판정.<br>최종: `SlotBoardManager.FindNearestCell`(거리 · 최근접 빈 셀)로 판정.
- **기물 이동** — 1차: Piece 오브젝트가 물리적으로 이동·복귀.<br>최종: Piece는 셀에 영구 매핑, 데이터만 이동(`SetByID`).
- **콜라이더** — 1차: 입력 판정에 사용.<br>최종: 입력 판정에서 제거(드래그 중 비활성만 유지).
- **효과** — 셀 사이 틈·손가락 오차·기물 가림 흡수 · 물리 쿼리 제거 · 항상 최근접 셀 스냅 + 호버 하이라이트.

### 3-3. 기물 공급 (`PieceSupplier` / `PieceSelector`)

- `PieceSupplier` — 대기 그룹 보유·슬롯 보충·재생성.<br>정원(2칸)을 못 채울 상황이면 아예 보충하지 않아 "1개짜리 슬롯"을 방지.
- `PieceSelector` — 보충 종류 우선순위 선정. 보드 동일 기물 2개 → 3개 → 대기 잔량 가중 랜덤.<br>1번째 선정을 보드 카운트에 +1 반영해 재탐색, 같은 슬롯 동일 기물 편중을 완화.

### 3-4. 슬롯 상태·비주얼·포탑 표시

- `SlotHealth`(IDamageable, HP·피격), `SlotRevive`(파괴→수리 카운트→부활), `SlotHealthBar`·`SlotRepairGauge`.
- `SlotDisplayController` — 슬롯 상태 + 포탑 유무를 종합해 표시 모드(Normal / +가동 / +대기 / 파괴)를 판정하고 요소를 일괄 토글.<br>4모드 × 여러 요소 조합이 흩어지지 않도록 한 곳에 집중.
- `SlotVisual`·`SlotFloor` — 프레임 이미지 교체, 파괴 바닥 교체 + 소팅 레이어 전환(몬스터와 앞뒤 관계 제어).

### 3-5. 포탑 대기열·오버소팅 (`SlotTurretQueue` / `SlotOverSorting`)

- 슬롯당 가동 1 + 대기 1을 참조로 보유.<br>`ITurretPresence`를 구현해 표시 컨트롤러에 자신을 주입(컨트롤러는 포탑 객체를 모름).
- 파괴 통보는 슬롯이 보유 — 포탑이 `OnDestroy`에서 통보(인터페이스 참조라 Unity-null 안전망이 없어 통보가 필수).
- 오버소팅(가동·대기 모두 찬 상태 추가 정렬 → 잔탄 과열 사격·입력 락)은 `SlotOverSorting`으로 분리.<br>큐는 판정·최종 동작만, "어떻게(탄배출·락·pending)"는 위임.

### 3-6. 게임오버 판정 (`SlotBoardManager`)

모든 슬롯이 Destroyed가 된 순간 전멸 이벤트(`OnAllSlotsDestroyed`)를 1회 발행. 상태 전환 이벤트를 단일 출처(`SlotRevive`)로 구독하고, 매번 전체 실측으로 판정해 부활 누락 위험을 회피합니다. (패배 화면 연결은 게임 플로우 측 이월)

## 4. 데이터 조회 계층

`PieceQuery` · `SlotQuery` · `StageQuery`의 대칭 구조입니다. 데이터 보유는 `DataManager`(CSV 자동 적재)에 위임하고, 도메인 조회·가공만 Query가 담당합니다.

- 스프라이트는 데이터가 이름(string)만 들고, Query가 SpriteTable에서 이름→객체로 변환(데이터/에셋 분리).
- 기물 90개 = 이름 6 × 성급 3 × 레벨 5.<br>카드 단위는 (이름·성급) 그룹 18개, 그 안의 레벨이 강화 단계. `UpgradeCost` 겸용(Lv1=해금 비용, Lv2~5=강화 비용).
- 임시 SO 조회에서 김경민 CSV 자동 생성 파이프라인으로 마이그레이션.

## 5. 아웃게임 (로비) UI

### 5-1. 로비 셸·탭 (`LobbyTabBar`)

로비 캔버스 5분리(BG/TopInfo/Window/UnderBar/Popup), CanvasScaler Expand 반응형. 탭 하나가 윈도우 전환 + 활성 표시 + 상단 라벨 갱신을 일괄 처리.

> 아웃게임 UI의 계층 구조·앵커/레이아웃·반응형·세이프 에리어 설계는 별도 문서 `아웃게임UI구조_이성규.md` 참조.

### 5-2. 덱 편성 (`DeckBuilder` / `DeckCard` / `DeckSlot` / `DeckHolder`)

- 보유 목록(18그룹 현재 레벨, 미보유 포함) 생성, 카드 탭으로 6칸 편성/해제, 재터치 해제.
- 강화로 그룹 대표 ID가 바뀌어도 편성을 유지하도록 `RemapSlots`로 슬롯 ID를 현재 레벨로 재매핑.
- 시작 시 편성 6개 ID를 `DeckHolder`(씬 간 static 다리)에 저장 → 인게임 진입 시 `SlotBoardManager`가 읽어 대기 그룹 구성.

### 5-3. 강화·해금 (`UpgradeWindow` / `PieceInventory` / `CurrencyDisplay`)

- 미보유 → 해금(스타더스트), 보유 → 강화(골드)로 재화 분리.<br>성공 시 `PieceInventory` 갱신 → `OnChanged` 이벤트로 목록·상세 즉시 재표시.
- `PieceInventory` — (이름·성급) 그룹 단위 보유·레벨 상태를 암호화 저장(JsonUtility + Encrypter + persistentDataPath).<br>선택 상태는 PieceID가 아니라 그룹 키로 보관(강화 시 ID가 바뀌므로).
- `CurrencyDisplay` — `RewardManager` 변경 이벤트 구독으로 상단 재화 즉시 갱신.<br>static 이벤트라 `OnDisable`에서 반드시 해제.

### 5-4. 스테이지 선택 (`StageSelectController` / `InGameBackground`)

이전/다음 순회, 일러스트 크로스 슬라이드 + 배경 크로스페이드(DOTween). 선택 StageID를 `StageManager`에 저장 후 덱 편성 시작에 위임. 인게임 배경은 로비 배경(BGID)과 다른 필드(INGameBG)로 분리.

### 5-5. 팝업 시스템 (`PopupBase` / `PopupManager` + 6종)

- `PopupBase`(추상, root 토글·Close 공통) + `PopupManager`(진입점·공용 딤 관리).<br>팝업이 딤을 직접 안 들고, 닫힘을 이벤트로 알리면 매니저가 공용 딤을 토글.
- 파생: `AlertPopup`·`LanguagePopup`·`CreditPopup`·`AttackTypePopup`·`SortPopup`·`PieceDetailPopup`.

### 5-6. 정렬·필터·상세보기 (`SortFilter` / `SortPopup` / `LongPressHandler` / `PieceDetailPopup`)

보유 상태·유형 필터(카드 재생성 없이 표시 토글로 편성 상태 유지). 카드 길게 누르기로 상세보기(스탯·일러스트 감상 모드). 롱프레스로 소비된 누름은 탭 처리를 거름(`Consumed` 플래그).

### 5-7. 튜토리얼 (`TutorialFlow` 등)

로비 셸 복제 + 페이지 전환(`TutorialFlow`). GIF 대체 스프라이트 루프(`SpriteLoopPlayer`), 스텝별 탭 선택·윈도우 전환(`TutorialTabSelect`·`TutorialWindowSwitch`). 로비 ? 버튼 진입 → 완료 시 로비 복귀.

### 5-8. 세이프 에리어 (`SafeAreaOffset` / `SafeAreaPadding`)

노치·홈 인디케이터 여백을 캔버스 스케일로 환산해 위치·오프셋에 반영. 계층 변경 없이 기존 오브젝트에 부착.

## 6. 현지화

- `LocalizationManager`(static) — Language enum ↔ Locale Code 매핑을 한 곳에 두고, 다른 코드는 enum만 안다.<br>저장은 PlayerPrefs, 앱 시작 시 복원.
- 한/영/일 3개 언어. Google Sheets → Unity Localization 단방향 파이프라인으로 기획팀이 문구를 직접 관리(프로그래머는 String Table 직접 수정 안 함).
- 정적 문구는 `LocalizeStringEvent`에 키만 꽂아 자동 갱신.<br>코드가 조립하는 동적 문구는 테이블 로드 완료를 기다린 뒤 갱신(로드 전 빈 값 대입 방지).
- TextMeshPro 폰트 폴백(NotoSansKR) 설정.

## 8. 대표 트러블슈팅 (발표용 요약)

발표 트러블슈팅 파트에 쓸 수 있는 사례입니다. 상세는 작업노트 해당 Day 참조.

1. **드래그 판정 재설계** — 콜라이더 "포인트 포함" 판정은 셀 사이 틈·기물 가림에서 조작감이 나빴음. 보드 최근접 셀(거리 비교)로 전환해 물리 쿼리를 제거하고 항상 최근접 셀로 스냅되게 개선.
2. **struct 상태 미반영** — C# struct의 박싱으로 상태 변이가 원본에 반영되지 않던 문제. 이미 힙 객체인 경우 class 전환으로 해결(GC 부담 미미).
3. **강화 결과 덱 반영** — 강화로 그룹 대표 ID가 바뀌어도 편성이 유지되도록 `OnEnable` 1회 갱신 + `RemapSlots`로 슬롯 ID 재매핑.
4. **Unity 씬 파일 YAML 병합 파손** — merge conflict 시 YAML 훙크 드롭으로 PPtr 누락. `.gitattributes`에 `*.unity binary`·`*.prefab binary` 지정으로 재발 방지.
5. **static 이벤트 구독 누수** — 씬 전환 시 죽은 참조 방지를 위해 static 이벤트 구독을 `OnDisable`에서 반드시 해제하는 규칙 확립.
6. **특전 시스템 모바일 ANR(에디터 정상/모바일 프리징)** — 에디터에서 안 보이던 두 결함이 모바일에서만 터진 사례. (1) 선택 가능 특전이 3개 미만일 때 이중 `while(true)`가 3개째를 못 채워 무한 루프, `timeScale=0`과 겹쳐 안드로이드 ANR. (2) 풀 구성이 `SlotBoardManager.Awake`보다 먼저 호출되는 초기화 순서 레이스로 소스가 비어 pool=0(특전 미표시). 해결: 선택 가능 수를 먼저 집계해 `min(3, 개수)`만 제시하고 0개면 페이즈 정상 종료, 룰렛 시도 상한(256)+결정적 폴백으로 종료 보장, 풀 구성을 특전 페이즈 첫 진입으로 지연해 Awake 완료를 보장. 더불어 특전 레벨 상태를 SO에서 런타임 Dictionary로 이관("SO에 동적 상태 두지 않음" 원칙 복귀) — 세션이 이어지는 모바일에서 특전이 만렙에 도달해 풀이 고갈되던 근본 원인을 제거.

# OBT 작업 계획 — 7팀

| 단계 | 기간 | 목표 |
|---|---|---|
| OBT | 6/24(화) ~ 6/30(월) | 콘텐츠 100% 완성 + 폴리싱 |
| OBT 이후 | 7/1(화) ~ 7/14(월) | 출시·QA·발표 준비 (신규 콘텐츠 없음, 안정화·버그·발표 집중) |

> OBT 7일 안에 콘텐츠를 마감하고, 이후 2주는 안정화·QA·발표에 집중. 즉 *CBT에서 골격만 있던 것·이월 Must를 이 7일에 완성*해야 함.

---

## 1. CBT 기간 회고

**완성된 것** — 아웃게임→인게임 메타-전투 연결(덱 편성→전투 반영), 3Sort 전투 코어 루프 1사이클, 데이터 매니저 자동화·파싱, 슬롯 데이터 정식화(파괴·부활·보충 우선순위), 타워 연결, 로비·덱 편성 UI.

**미완성(골격만)** — 특전 효과, 웨이브 데이터 적용(몬스터 1종), 스테이지 세분화. (정식 데이터는 임시로 동작 중 — 정식 CSV가 OBT 이후 도착해 값 교체 예정)

**체크 못 한 항목 원인**
* 특전 효과·웨이브 다양화 등은 *CBT 기간 볼륨 대비 3인 분량 초과* — 선택·UI·생명주기 등 골격을 우선 넣고 효과·데이터 적용은 OBT로 이월.
* 일부 일정 지연 — 담당 폭이 넓어 한 영역(예: UI) 지연이 병합 일정에 영향(병합 하루 연기).

## 2. OBT 작업 계획 — 콘텐츠 완성

> CBT 골격 위에 *완성·교체*하는 것이 대부분. 신규 설계보다 채우기·연결.

**미완성 콘텐츠 (OBT 내 반드시 완성 = Must)**

| 항목 | 현재(CBT) | OBT 완성 목표 | 담당(예상) |
|---|---|---|---|
| 스테이지·웨이브 데이터 적용 | 생명주기·1종 몬스터 | 웨이브 데이터로 몬스터 다종, 스테이지 세분화 | 김경민/안정연 |
| 특전 효과 구현 | 선택·UI까지 | 선택 시 실제 효과 적용 | 김경민 |
| 게임 오버 이벤트 | 미구현 | 전 슬롯 파괴 시 게임 오버 처리 | 이성규(게임플로우) |
| 슬롯 복구 시스템 | 부활 골격 | 복구 정식화 | 이성규 |
| 몬스터 종류 확장 | 1종 | 다종·데이터 연결 | 안정연 |

> 정식 데이터 교체는 *OBT 이후*(정식 CSV 도착 시) 값 교체 — OBT 기간은 임시 데이터로 위 기능을 완성.

**데이터 전제** — 정식 CSV 완성본은 *OBT 이후 도착 예정*. OBT 기간엔 *임시 데이터로 개발 진행*, 기획팀이 OBT 동안 정식 데이터를 점진적으로 채움. 임시→정식은 *값 교체*라(DataManager ID 조회 구조 유지) 기능 개발이 데이터 도착에 묶이지 않음 — 데이터는 병목 아님.

**일정 현실성 점검**
* 7일에 위 Must를 다 넣으려면 *병렬 진행* 필수 — 각자 담당이 분리돼 있어 동시 작업 가능.
* 핵심 부담은 *데이터가 아니라 기능 구현 볼륨* — CBT에서 골격만 넣고 효과를 못 끝낸 항목(특전 효과 등) + 새 Must를 7일에 다 채워야 함.
* [회의 확인] 각 항목 *예상 소요·담당 확정*, 7일에 정말 다 되는지 / 일부는 범위 조절할지 현실 점검.

## 3. OBT 작업 계획 — 폴리싱

**아트 리소스 (그래픽·사운드·이펙트)**
* [회의 확인] 적용 필요한 아트 에셋 목록 — 기물·포탑·몬스터 스프라이트 정식본, 슬롯 포탑 비주얼 정보
* 사운드 — BGM·효과음 (현재 없음 → 기초 적용 목표)
* 이펙트 — 정렬 성공·포탑 발사·피격 등 (우선순위 낮음, 여유 시)

**UI/UX 개선 필요 화면 (이성규)**
* 덱 편성 — 미보유 표시, 정렬/정보 버튼, 초상화 배경, 프레임 등급색 (CBT 후순위로 남긴 세부)
* 덱 카드 스크롤 — 일부 기기 스크롤 영역 이탈 수정, 해상도 대응 마무리
* 고정 라벨 이미지화 — TMP 아웃라인 한계분, 현지화 대비 (우선순위 낮음)
* 슬롯 포탑 비주얼 정보 추가
* 전반 해상도 대응 마무리 — 다양한 화면비

**게임 연출 (카메라·트랜지션·피드백)**
* 씬 전환 — 로비 ↔ 인게임 트랜지션 (현재 즉시 전환)
* 피드백 — 정렬 성공·포탑 소환·피격 시 시각/청각 피드백 (타격감)
* [회의 확인] 전투 카메라 연출 필요 구간

## 4. 예상되는 가장 큰 리스크 1개

**리스크: 7일 안에 콘텐츠 100% 완성 — 구현 볼륨 대비 일정 부족**
* OBT는 7일뿐이고, *CBT에서 골격만 넣고 못 끝낸 항목*(특전 효과 등) + 새 Must를 *이 7일에 다 채워야* 함. 3인 분량으로 빡빡.
* **OBT 이후엔 신규 콘텐츠 금지** — 7일에 못 끝낸 콘텐츠는 *갈 데가 없음*(이후는 안정화·QA·발표만). 즉 *이번에 못 넣으면 출시에서 빠짐*.
* 3인 구조라 한 명 막히면 해당 영역 정지 — CBT에서 겪은 병목과 동일.

**대응 계획**
* **Must를 핵심만 좁히기** — 7일에 다 안 되면, *출시에 꼭 필요한 것*과 *빠져도 되는 것*을 먼저 갈라 *진짜 Must에 집중*. 욕심내 다 손대다 *전부 어정쩡*해지는 것 방지.
* **중간 진척 체크(6/26~27)** — 절반 시점에 *안 될 것 같은 항목을 일찍 식별* → 범위 조절(축소·제외)하거나 도움 요청. 막판 "안 됐어요" 방지.
* **콘텐츠 우선, 폴리싱 후** — 콘텐츠 100%가 Must라, *폴리싱은 콘텐츠 끝난 뒤 여유분*으로. 폴리싱 욕심에 콘텐츠가 밀리지 않게 순서 고정.
* 막히면 학원 측 기술 지원 가능성 열어두기.

# 배틀 연결 명세서 — 3-Sort ↔ 포탑 소환

**작성자**: 이성규 (B / 3-Sort)  
**대상**: 안정연 (C-2 / 포탑 소환·전투)  
**목적**: 정렬 성공 → 포탑 소환 통합 연결 합의  
**작성일**: 2026-06-04  

---

## 1. 한 줄 요약

3-Sort에서 *슬롯 정렬 성공*이 나면 `SlotBoardManager.OnSortSuccess(slotID, pieceID)` 이벤트가 발행된다.
포탑 소환 쪽은 이 이벤트 **하나만 구독**하면 9슬롯 전부의 정렬 성공을 받는다.

---

## 2. 연결 지점 (B → C-2)

### 발행 측 (이성규)

```csharp
// SlotBoardManager — 9슬롯의 정렬 이벤트를 한 곳으로 모아 외부에 발행
public event Action<int, int> OnSortSuccess;  // (slotID, pieceID)
```

- **slotID** — 정렬이 일어난 슬롯 번호 (0~8). 소환 *위치* 결정용
- **pieceID** — 정렬된 기물 종류 ID (1~6). 소환할 *포탑 종류* 결정용

### 구독 측 (안정연) — 예시

```csharp
void Start()
{
    _boardManager.OnSortSuccess += OnSortSuccess;
}

void OnDestroy()
{
    if (_boardManager != null)
        _boardManager.OnSortSuccess -= OnSortSuccess;
}

void OnSortSuccess(int slotID, int pieceID)
{
    Vector3 pos = _boardManager.GetSlotByID(slotID).transform.position;
    // pos 위치에 pieceID 종류의 포탑 소환 (또는 대기열 등록)
}
```

---

## 3. 슬롯 위치 얻기

소환 위치는 *슬롯 Transform*에서 가져온다.

```csharp
Slot slot = _boardManager.GetSlotByID(slotID);
Vector3 pos = slot.transform.position;
```

- `GetSlotByID(int)` — SlotID로 슬롯 직접 접근 (SlotID = 리스트 인덱스 보장됨)
- **주의** — 슬롯 위치는 `SlotBoardLayout`이 *화면 해상도에 맞춰 동적 배치*한다. 고정 좌표 아님.
  포탑이 슬롯에 붙어야 하면 *소환 시점의 슬롯 position*을 쓰거나, 슬롯 자식으로 붙이는 방식 권장.

## 4. 합의 필요 항목

| # | 항목 | 이성규(B) | 안정연(C-2) 확인 필요 |
|---|---|---|---|
| 1 | 연결 방식 | 이벤트 구독 발행 완료 | 구독 vs 직접 호출 중 택 |
| 2 | pieceID → 포탑 매핑 | pieceID(1~6) 전달만 | 포탑 종류 변환은 C-2에서 |
| 3 | 소환 위치 | 슬롯 Transform 제공 | Vector3 위치 변환은 C-2에서 (기존 합의) |
| 4 | 같은 슬롯 재소환 | B는 정렬마다 발행 | 이미 포탑 있을 때 처리(교체·대기열)는 C-2 |
| 5 | 해상도 변경 시 | 슬롯 위치 바뀜 | 소환된 포탑도 따라갈지 — ScreenWatcher 구독 검토 |

## 5. 해상도 대응 연계 (ScreenWatcher)

화면 해상도가 바뀌면 슬롯 위치도 바뀐다. 포탑이 *슬롯에 고정*돼야 하면 두 방법:

- **A. 포탑을 슬롯 자식으로** — 슬롯이 움직이면 자동으로 따라옴 (HP바·셀과 같은 방식)
- **B. ScreenWatcher 구독** — 화면 변경 시 포탑도 재배치

```csharp
// 적 스포너·포탑 매니저도 같은 채널 구독 가능
ScreenWatcher.Instance.OnResolutionChanged += RepositionTowers;
```

데모 단계는 해상도 고정(S23 Ultra)이라 *급하지 않음*. CBT에서 다양한 기기 대응 시 결정.

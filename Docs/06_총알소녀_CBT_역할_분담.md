# 총알소녀 CBT 역할 분담

> CBT 구간(~06/22) 플밍 역할 정리. 담당 영역은 데모와 그대로 이어가되,
> 데모에서 미룬 항목·디테일 구현·임시 → 데이터(SO) 교체를 채우는 단계다.
> 데모 회의자료처럼 항목을 펼치지 않고, 각자 남은 것 위주로만 간결하게 잡는다.
>
> 핵심 성격: **새로 짜기보다 ① 임시 구현을 데이터로 교체 ② 미뤄둔 디테일·비주얼 채우기**.

---

## 담당 (데모와 동일)

| 담당 | 영역 |
|---|---|
| 이성규 | A(코어 인프라)·B(3-Sort 슬롯·기물) · 게임 플로우 · F(UI·UX, 데모 이후) · 팀 허브 |
| 안정연 | C-1(몬스터) · C-2(포탑·발사) (부팀장·PM·서기) |
| 김경민 | D(로그라이크) · E(보상·가챠) · G(데이터 드리븐) |

---

## 이성규 — B(3-Sort) · 게임 플로우 · F(UI·UX)

**임시 → 데이터(SO) 교체**

- 기물 enum·스프라이트 배열 → 기물 SO 조회로 교체 (Day 12에 박아둔 `_data.Sprite` 자리)
- 공급기 임시값(`PrepareWaitingGroup` 50개 등) → 데이터 기반으로
- 외부 인터페이스(`PieceID` 등)는 그대로, 내부 구현만 교체

**B 잔여·디테일**

- `PieceSelector` — 우선순위 배치(동일 2개 → 3개 → 랜덤). 6종 됐으니 이제 의미 있음
- `WaitingGroup` 전용 자료구조 정식 분리
- 슬롯 HP 부가 규칙 — 수리(파괴 슬롯 여러 번 정렬), 정렬 성공 시 소량 회복, 모든 슬롯 파괴 = 게임오버 이벤트
- 데드락 대응 — 검사 시점·처리(REROLL/리필) 기획 확인 후
- 비주얼 갱신 디테일

**게임 플로우 (D 흡수분)**

- 웨이브 타이머, 진입·종료 이벤트
- 스테이지 진행(10웨이브), 보스 트리거(5/10), 스테이지 클리어 판정

**메타 진행 루프 (인게임 바깥 — 게임 플로우·F)**

> 데모는 인게임 한 판만. CBT는 *로비 → 스테이지 선택 → 플레이 → 정산 → 재화 → 덱 편성 → 다시 플레이* 전체 루프가 돌아야 함. 인게임 안정화 후 단계.

- 스테이지 선택 (로비 → 스테이지 고르기)
- 스테이지 종료 흐름 (결과 → 정산 → 로비 복귀) — 흐름은 본인, 메커니즘은 김경민(D-9)
- 덱 편성 (#12 — 게임 플로우 관계로 본인 담당). 재화·기물 활성화는 E(김경민)와 연계

**F (CBT 본 작업)**

- 인게임 HUD (슬롯 HP·웨이브·시간·경험치 게이지)
- 슬롯 위 원형 게이지 + 탄창 숫자 (포탑 담당과 연계)
- 로비·스테이지 선택, 옵션, 정산 페이지
- uGUI 아틀라스 전략 (한 화면 = 한 아틀라스)

## 안정연 — C-1(몬스터) · C-2(포탑·발사)

> 전투 기초(몬스터 스폰·이동·근접 공격)는 데모에서 완료. CBT는 그 위에 타입·시스템을 얹는 단계.

**C-1 잔여**

- 몬스터 SO 연결, 오브젝트 풀링(누적 처치 수천 단위)
- 5웨이브 중간보스 / 10웨이브 최종보스
- 처치 이벤트 — D(경험치)·E(드롭)와 연결

**C-2 잔여**

- 포탑 SO (공통 + 타입 의존 필드), 등급제·레벨업(조각)
- 탄창(원형 게이지·숫자, F와 연계), 발사체 풀링
- 관통·폭발·효과형 처리
- 포탑 타입 다종 구현 (데모는 최소 1종, CBT에서 확장)

---

## 김경민 — D(로그라이크) · E(보상·가챠) · G(데이터)

> G(데이터)는 기반 완료 — CSV 파싱·DataManager 구현됨. CBT는 그 기반 위에 로그라이크 본체 골격.

**D — 로그라이크 본체 골격**

- 레벨업·경험치 누적, 레벨별 경험치 곡선(데이터 참조)
- 특전 SO 정의, 풀에서 선택지 뽑기(레벨·이전 선택 반영)
- 특전 적용 → 슬롯·포탑 스탯 반영 (이벤트)
- 정비창 — 웨이브 종료 시 오픈, 누적 레벨업 일괄 선택, 보유 특전·스탯 확인

**E**

- 경험치 드롭·자동 흡수·드롭 오브젝트 풀링
- 정산 보상 표시 데이터 공급, 스테이지 종료 메커니즘(D-9, 흐름은 이성규)
- 재화·기물 활성화 (플레이 재화로 덱 기물 해금 — 덱 편성 UI는 이성규)
- 가챠 (후순위 — 핵심 루프 완성 후)

**G 잔여**

- 데이터 회의 갱신 지속 (기획팀과)
- 로드 시점 유효성 검사, 현지화 시트, 스키마 표준 점검

## 기획 리뷰 타임에서 받을 것 (기획 → 플밍)

> 다음 주 기획팀 리뷰 타임은 기획 → 플밍 전달 방향. 작업하며 *기획 확인 필요*로 남겨둔
> 미확정 항목을 한 번에 받는 자리. 받아야 CBT 구현이 막힘 없이 들어감. 들고 갈 체크리스트.

- **데드락 처리** — 6종이라 초기 배치 안 맞을 가능성. 검사 시점·처리(REROLL/리필)
- **슬롯 HP 부가 규칙** — 수리(파괴 슬롯 정렬)·정렬 시 회복·게임오버 조건. 기획서 SlotRuntimeData(HP·State·Repair) 데모 후 활성 범위
- **빈 슬롯 새 기물 배치 타이밍** — 즉시 / 연출 후
- **메타 루프 디테일** — 스테이지 선택 구성, 재화 종류·획득량, 기물 활성화 비용, 덱 편성 규칙
- **SO 스키마 확정** — 기물·몬스터·포탑 SO 필드 구조 (G-2, 데이터 회의 연장). *교체 작업의 선행 조건*

---

## CBT 초반에 먼저 맞출 것 (인터페이스 합의)

각자 골격 들어가기 전에 *시스템이 만나는 이벤트 시그니처*를 먼저 합의 (Day 6 WaveManager 방식 — 읽기 전용 프로퍼티 + 이벤트).

- **게임 플로우(이성규) → 정비창(김경민)** — 웨이브 종료 이벤트 구독해 정비창 오픈
- **특전(김경민) → 슬롯·포탑(이성규·안정연)** — 특전 적용이 스탯 바꾸는 인터페이스
- **C-1(안정연) → D·E(김경민)** — 처치 이벤트 → 경험치·드롭
- **정비창 UI 경계** — 로직은 김경민(D), 통합 UI는 이성규(F). 골격 단계는 각자 임시 UI로 검증

---

## 의존 순서 (막힘 방지)

- **기획 리뷰 → SO 스키마 → 교체** — 리뷰 타임에서 미확정 항목 받고, 데이터 회의로 SO 필드 확정된 것부터 임시 → SO 교체
- **인게임 안정화 → 메타 루프** — 스테이지 선택·재화·덱 편성은 *재화가 쌓이고 기물 풀이 있어야* 의미. 인게임 루프(SO 교체·디테일) 안정 후 얹는 후반 단계
- **교체는 각자 영역 안에서 독립** — 인터페이스(OnSortSuccess 등) 안 건드리면 통합 연결 유지됨. 내부만 교체
- **월요일 통합 연결을 CBT 교체가 깨지 않게** — 교체는 내부 구현이라 인터페이스 보존 시 통합 살아있음

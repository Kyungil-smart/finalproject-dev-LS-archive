# CBT 마감 체크리스트 — 7팀

CBT 기간(6/10~6/23) 마감. 팀원: 이성규, 김경민, 안정연

**플레이 루프로 설명**
로비에서 덱 편성 → 인게임 진입 → 몬스터가 슬롯 공격 → 3-Sort 정렬 → 포탑 소환 → 몬스터 처치 → 웨이브 진행. **아웃게임(메타) → 인게임 전투의 한 흐름이 도는 상태**(CBT 6/23 제출 기준). 데모(6/8)의 전투 코어 루프 위에 메타 진행을 붙임.

## 1. 공통 체크리스트 (회고)

### 1-1. 플레이 루프 연결

* **처음부터 끝까지 끊김 없이 동작하는가?** — 예. 로비 → 덱 편성 → 인게임 → 3Sort → 포탑 소환 → 전투 → 웨이브가 끊김 없이 이어짐.
* **최소 1사이클 이상 플레이 가능한가?** — 예. 아웃게임(메타) → 인게임 전투 한 사이클 동작.

### 1-2. 콘텐츠 완성도 — MVP 점검

* **어떤 게임인지 이해 가능한가?** — 예. 덱을 짜고 → 같은 기물 3개를 정렬해 포탑 소환 → 몬스터를 막는 *3정렬 디펜스*임이 플레이로 드러남.
* **시스템만이 아니라 플레이 콘텐츠가 보이는가?** — 예. 덱 편성·정렬·포탑 소환·전투가 화면에서 실제로 동작.
* **데모 대비 추가 콘텐츠가 루프에 기여하는가?** — 예. 핵심 추가분 *덱 편성 → 인게임 반영*이 "어떤 기물로 싸울지"를 정하게 해 전투 루프 앞단을 만듦.

**완료 (CBT 빌드)**

* 전투 코어 루프 (데모부터) — 3Sort 드래그·정렬·보충·재생성, 기물 6종, 슬롯, 포탑 소환, 몬스터
* 아웃게임/메타 (신규) — 로비(탭 전환), 덱 편성(6칸·인게임 반영), 씬 흐름
* 인게임 정식화 — 슬롯 데이터 구조, 파괴·부활, 보충 우선순위, 타워 연결
* 데이터/스테이지 — 데이터 매니저 자동화·파싱, 특전 무작위 선택·UI, 스테이지 생명주기
* 전투 — 몬스터 종류·데이터 연결

**부분 완료 / 골격만 (빌드에 들어갔으나 미완)**

* 특전 — 선택·UI는 됐으나 *효과 미구현*
* 웨이브 — 데이터 미적용으로 몬스터 1종 (확장 예정)
* 스테이지 — 생명주기는 있으나 *세분화 미구현*
* 데이터 — 임시로 동작, 정식 교체 전

### 1-3. 범위 정리 — 우선순위 점검

* **Must / Nice / Won't 구분이 명확한가?** — 예 (아래).
* **Must 항목이 모두 구현 완료되었는가?** — **CBT Must(메타→전투 연결, 핵심 루프 1사이클, 데이터 파싱)는 완료.** 특전 *효과*·웨이브 *다양화* 등은 골격까지만 들어가 OBT Must로 이월.

**CBT Must (완료)**

* 아웃게임 → 인게임 메타-전투 연결 (덱 편성 → 전투 반영)
* 3Sort 전투 코어 루프 1사이클
* 데이터 매니저 자동화·파싱

**OBT Must (이월 — CBT 골격 위에 완성)**

* 스테이지·웨이브 데이터 적용 (몬스터 1종 → 다종)
* 특전 효과 구현 (CBT는 선택·UI까지)
* 임시 → 정식 데이터 교체
* 게임 오버 이벤트 (전 슬롯 파괴), 슬롯 복구 시스템

**Nice to Have (여유 시)**

* 메타루프 확장 (재화·강화·해금), 포탑 등급·탄창·발사체 다양화, 타워·기물 세부 매칭, UI 폴리싱·해상도, 사운드 기초

**Won't (제외)**

* 현지화 UI, 이펙트·연출 폴리싱, 콤보·필살기, 보상 시스템

### 1-4. 빌드 안정성

* **크래시 없이 정상 실행되는가?** — 예. APK 설치·실행 정상.
* **주요 흐름에 치명적 버그가 없는가?** — 핵심 루프(편성→전투→웨이브)는 치명 버그 없이 진행. 비치명 잔여 이슈는 인지·기재 — 투사체 타겟 상실 시 탄환 잔류, 일부 기기 덱 카드 스크롤 이탈, 슬롯 포탑 비주얼 정보 미흡.

## 2. 7팀 콘텐츠 완성도 (회고)

루프: 3Sort → 전투 강화 → 웨이브 진행

* **3Sort → 전투 강화 → 웨이브 루프가 끊김 없이 동작하는가?** — 동작. 단 웨이브는 데이터 미적용으로 몬스터 1종 범위.
* **3Sort 결과가 전투 결과에 영향을 미치는가?** — 예. 정렬 성공 → 해당 종류 포탑 소환 → 그 포탑이 전투 수행. 정렬이 곧 전투력.
* **로비 → 맵 → 전투 → 특전 흐름이 1사이클로 동작하는가?** — 흐름 동작. 특전은 선택·UI까지(효과 미구현), 스테이지는 생명주기까지(세분화 미구현).

## 3. CBT 기간 회고 — KPT 점검

> CBT 킥오프(6/10) 데모 회고 기준 — 유지/개선/도전 갱신.

**리스크 (가장 큰 1개)** — 3인 팀이라 담당 폭이 넓어, 1명이라도 막히면 해당 영역이 정지되는 병목 구조. CBT 구현 볼륨도 상대적으로 많았음. 지속적 작업 페이스·건강 관리 필수.

**Keep**

* 작업 현황 공유 방식
* 기획 전달 방식 — 개발 기간 전환 시기 전체 리뷰, 기획 문서 허브시트 업데이트
* (추가) 코어를 먼저 탄탄히 잡아 후반에 메타·UI를 얹을 여유 확보 — 데모 전투 루프 위에 CBT 메타를 무리 없이 붙임

**Problem**

* 3인이라 담당 폭이 넓어 1명이라도 막히면 해당 영역 정지 — **이번 CBT 병합 시 실제 발생**(한 팀원 UI 작업 지연으로 병합 하루 연기)

**Try**

* 기능 범위를 일찍 합의하고, 못 낼 것 같으면 미리 범위에서 빼거나 축소 — 막판 "안 됐어요"로 전체가 밀리는 것 방지
* 중간 진척 체크로 지연을 일찍 드러내기
* 담당 간 연결은 인터페이스로 미리 열어 본인 작업이 상대를 기다려 멈추는 것은 줄임 (단, 기능 자체 지연은 범위 조절로 대응)
* 막힐 시 학원 측 기술 지원 도움 가능성 열어두기

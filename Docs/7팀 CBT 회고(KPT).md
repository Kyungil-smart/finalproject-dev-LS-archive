# 미니 Problem

## 1. 현재 구현 완료 기능 — MVP 점검


**플레이 루프로 설명**  
몬스터가 슬롯 공격 → 3-Sort 정렬 → 포탑 소환 → 몬스터 처치 → 웨이브 진행. **코어 루프 1회전이 버그 없이 도는 상태**(데모 6/8 제출 기준).

**완료 (MVP 핵심 루프)**

* 전투
* 3-Sort: 드래그 배치, 정렬 판정, 빈 칸 보충·재생성, 기물 6종 비주얼
* 슬롯 시스템
* 포탑 소환 (기본)
* 몬스터 (기본)
* 데이터 파싱 기능
  * 데모에 포함은 안되었지만 추후 데이터 연결 기능을 위하여 사전 개발

**미완료 (데모 범위 외 = CBT 대상)**

* 기물 배치 우선 순위
* 특전 시스템
* 스테이지 시스템, 웨이브 시스템
* 로그라이크
* 메타루프 - 로비, 덱편성, 재화, 강화 및 해금 시스템
* 데이터 연결

## 2. OBT 추가 예정 기능 — 우선순위 점검

**Must (핵심 루프 완성에 필수)**

* 게임 플로우 디테일
  * 스테이지 웨이브
  * 게임 오버 이벤트(모든 슬롯 파괴)
* 로그라이크 (특전 시스템)
* 임시 데이터 연결 → 정식 데이터 교체
* 슬롯 복구 시스템
* 몬스터 종류 구현

**Nice to Have (일정 여유 시)**

* 메타루프 - 로비, 덱편성, 재화, 강화 및 해금 시스템(로비)
* 포탑 등급 탄창 발사체 타입 다양화
* 타워 및 기물 종류 세부 구현 및 매칭
* UI 및 사운드 등 디테일 기초

**Won't (이번 CBT 제외)**

* 현지화 UI 적용
* 이펙트 및 비주얼적 추가 연출(폴리싱)
* 콤보, 필살기등 
* 보상 시스템

## 3. 가장 큰 리스크 1개 — KPT 점검

**리스크:** 3명이라는 적은 팀원으로인해 전원의 작업 분량 부담이 큰점
- 지속적 작업 페이스 및 건강 관리 필수
- CBT 기간 구현 볼륨이 상대적으로 많은편

## KPT
Keep(유지할 것), Problem(개선할 것), Try(새롭게 도전할 것)

* **Keep**:
  * 작업 현황 공유 방식
  * 기획 전달 방식
    * 마일스톤 산정등이 필요한 개발 기간 전환 시기에 전체적인 리뷰 진행
    * 기획 문서 허브시트의 업데이트 방식
* **Problem**:
  * 3인이라 각자 담당 폭이 넓어 1명이라도 이슈가 생길시 병목 가능성이 높음
    * 한 명 막히거나 빠지면 해당 영역 정지
* **Try**:
  * 막힐 시 학원 측 기술 지원 도움 가능성 열어두기

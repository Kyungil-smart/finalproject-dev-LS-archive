# 1. 로그라이크, 특전 시스템

## 개요
인게임 상태 변화(전투, 특전 선택)에 따라 UI 윈도우의 상태를 동적으로 제어하고, 데이터를 사용자 인터페이스에 출력하는 일련의 시스템 구현

## 구현 사항
### Event Driven Architecture
* `StageManager`와 `PerksManager`의 싱글톤 인스턴스 이벤트를 활용하여 UI 갱신 로직을 상호 결합성이 낮게 연결
### Stage Condition Check
* `StageManager`에서는 Timer와 Monster의 처치 수 두 가지 조건을 확인하여 Wave 승리 여부를 확인하고, Slot의 체력 상태로 패배 여부 확인
### Perks Condition Check
`ExpManager`가 `MonsterController`의 static Event를 구독하여, 몬스터가 처치될 때 마다 경험치를 증가시키고 경험치 증가 및 레벨 업 시 마다 이벤트를 발생시켜 UI 및 특전 획득 횟수를 증가시킴


# 2. Csv Parser

## 개요
CSV 형식의 기획 데이터 문서를 Unity SO Asset으로 자동 생성하도록 지원해주는 유틸리티 Editor 코드를 구현하여 Human Error 방지, 기획-개발 협업 편의성 지원

Reflection을 Unity Runtime이 아닌 Editor Time으로 격리시켜 게임 프로그램에 성능 상 영향을 주지 않음.

## 구현 사항
기획팀과 자료형, 변수 명, ID 기준 컬럼, 주석(comment) 영역을 협의하여 정한 양식을 기준으로 CSV 파일을 분석하여 SO Class를 정의하는 `C#` 코드 파일 생성

### Parsing
* Csv 파일의 스키마를 분석하여 유니티 `SO` 클래스 코드를 실시간 덤프
### Reflection
* `C#`의 Reflection을 활용해 CSV 문자열 필드를 생성된 SO 클래스 데이터 구조에 주입
### Expand
* 신규 테이블 추가 시 `DataManager` 내 로드 파이프라인 코드를 텍스트 마킹 스캔 방식으로 자동 생성 및 갱신

### 세부 명세
#### Dynamic Assembly 추적을 통한 스크립트 컴파일 연동

1. 신규 CSV 파일 생성 시 `GenerateSOClass()`가 `C#` 파일을 디스크에 생성함.

2. 스크립트 생성 직후 유니티의 도메인 리로드 및 컴파일 시차로 인해 발생할 수 있는 참조 에러를 해결하기 위해, `AppDomain.CurrentDomain.GetAssemblies()`를 순회하며 컴파일 완료된 메타데이터 타입을 실시간 추적 기법으로 검증 및 연동함.

#### 리플렉션(Reflection) 기반 데이터 직렬화 메커니즘
1. Csv의 Row를 순회할 때 하드코딩된 변수 대입문을 배제하고 `soType.GetField()`를 통해 런타임에 메모리 상의 변수명을 역추적함.

2. `Convert.ChangeType()` 및 사용자 정의 타입 변환 함수(`ConvertType`)를 결합하여 문자열(String)로 들어오는 원시 데이터를 int, float, bool 등의 타겟 타입으로 런타임 안전하게 박싱/언박싱하여 주입함.

# 3. Data Manager

## 개요
`CSVParser`에 의해 자동 생성된 다수의 `SO` 에셋을 인게임 프로세스 실행 시 메모리에 일괄 로드하고, 콘텐츠 로직 코드에서 ID 기반으로 `O(1)`의 시간복잡도로 실시간 질의(Query)할 수 있는 중앙 집중형 데이터 관리 싱글톤 클래스 정의.

`Dictionary<Type, object>` 구조의 루트 딕셔너리로 Type과 무관하게 데이터를 딕셔너리 형태로 관리하는 체계를 구축함. 타입 자체를 Key로 삼아 하위 데이터 테이블`(Dictionary<int, T>)`을 업캐스팅하여 보관하는 다형성 기반 아키텍처.

## 구현 사항

### 1. 제네릭(Generic) 기반의 인덱싱 쿼리
* `GetData<T>(int id)` 및 `GetTable<T>()` 메서드는 `C#` 제네릭 제약 조건`(where T : ScriptableObject)`을 활용하여 컴파일 타임에 타입 안정성을 완벽히 보장함.

* 런타임에 다운캐스팅 연산`(obj as Dictionary<int, T>)`을 통해 내부 서브 테이블을 안전하게 복원한 뒤, 인덱싱(`O(1)`)으로 특정 SO 인스턴스를 즉각 반환함.

### 2. 리플렉션을 이용한 식별자(ID) 추출 및 예외 통제
* SO 에셋이 로드될 때, 매니저가 각 데이터 클래스의 고유 Key를 수동으로 매핑하지 않고 `GetIdFromSO()` 내에서 `FieldInfo.Name.EndsWith("ID")` 조건으로 메모리를 스캔함.

* 중복 ID 발생 시 Debug.LogError를 발생시켜 데이터 오염을 샌드박스 단계에서 차단함.

### 3. 데이터 무결성(Immutability) 보장을 위한 인터페이스 설계
콘텐츠 코드에서 테이블 전체를 순회하거나, `DataManager.Instance`를 여러 번 참조하지 않고 데이터에 접근할 수 있도록 `GetTable<T>()`를 제공하되, 원본 데이터 딕셔너리를 그대로 노출하지 않고 `IReadOnlyDictionary<int, T>` 자료형으로 래핑하여 반환함.

이를 통해 외부 레이어에서 실수로 데이터를 추가/삭제/수정하는 사이드 이펙트를 원천 차단하고 데이터의 읽기 전용 무결성을 강제함.
